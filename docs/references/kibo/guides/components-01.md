### Announcement

- `Announcement` is a `Badge` wrapper. It defaults `variant` to `"outline"` (unlike the helper Badge's `"default"`), accepts all Badge props, has `themed?: boolean`, and forwards remaining props ([component](../upstream/packages/announcement/index.tsx#L5-L24); [Badge contract](../upstream/packages/shadcn-ui/components/ui/badge.tsx#L7-L46)). `asChild` is consequently available through the inherited Badge props.
- `AnnouncementTag` and `AnnouncementTitle` are plain `div`s with `HTMLAttributes<HTMLDivElement>`; both apply truncation. `themed` adds the parent `announcement-themed` class and changes the tag background only through a CSS group selector ([source](../upstream/packages/announcement/index.tsx#L27-L53)).
- **Documentation mismatch to keep in mind:** the docs call this “context-based theming” ([docs](../upstream/apps/docs/content/components/announcement.mdx#L12-L17)), but this implementation has no React context; it uses the CSS group class above.
- Demos: basic tag/title with a Lucide arrow ([`announcement.tsx`](../upstream/apps/docs/examples/announcement.tsx#L3-L18)); four custom color class variants with `themed` ([`announcement-themes.tsx`](../upstream/apps/docs/examples/announcement-themes.tsx#L3-L58)); a tagless form ([`announcement-tagless.tsx`](../upstream/apps/docs/examples/announcement-tagless.tsx#L3-L15)); and the separate Hero block demo wraps it in a Next `Link` ([`hero.tsx`](../upstream/apps/docs/examples/hero.tsx#L12-L16), [`hero.tsx`](../upstream/apps/docs/examples/hero.tsx#L76-L84)). The link is demo composition, not intrinsic Announcement behavior.

### Avatar Stack

- Props are `children: ReactNode`, optional `className`, `animate` (default `false`), and pixel `size` (default `40`) ([source](../upstream/packages/avatar-stack/index.tsx#L4-L17)). It maps truthy children into circular wrappers; subsequent items receive a `maskImage` radial gradient calculated from `size` ([source](../upstream/packages/avatar-stack/index.tsx#L26-L49)). This is source-level CSS only; mask rendering was not browser-tested.
- The component specifically sizes descendants carrying `data-slot="avatar"`, which the local shadcn `Avatar` root supplies ([stack](../upstream/packages/avatar-stack/index.tsx#L32-L43); [helper](../upstream/packages/shadcn-ui/components/ui/avatar.tsx#L8-L21)). Other child shapes are not normalized by the implementation.
- `animate` only changes CSS: the stack expands spacing on hover and child wrappers get transitions ([source](../upstream/packages/avatar-stack/index.tsx#L18-L23)). The caller `className` is merged onto both the outer stack and every generated wrapper ([source](../upstream/packages/avatar-stack/index.tsx#L18-L24), [L32-L37](../upstream/packages/avatar-stack/index.tsx#L32-L37)); account for that double application when using size/layout utilities.
- Demos: four remote-image shadcn avatars ([`avatar-stack.tsx`](../upstream/apps/docs/examples/avatar-stack.tsx#L3-L25)), the same with `animate` ([`avatar-stack-hover.tsx`](../upstream/apps/docs/examples/avatar-stack-hover.tsx#L3-L25)), and the Collaborative Canvas block with animated `size={32}` avatars ([`collaborative-canvas.tsx`](../upstream/apps/docs/examples/collaborative-canvas.tsx#L1-L10), [`collaborative-canvas.tsx`](../upstream/apps/docs/examples/collaborative-canvas.tsx#L113-L124)). Remote image URLs and canvas movement are demo data/behavior, not AvatarStack behavior.

### Banner

- `Banner` takes `visible?`, `defaultVisible?` (default `true`), `onClose?`, `inset?` (default `false`), and div attributes. It delegates state to `useControllableState`, passing `visible` as `prop`, `defaultVisible` as `defaultProp`, and `onClose` as `onChange`; it renders `null` when `show` is false ([source](../upstream/packages/banner/index.tsx#L25-L64)). This is the evidence for controlled/uncontrolled visibility; the external hook itself was not executed or independently inspected.
- `BannerClose` gets `setShow` from `BannerContext`, sets it to `false`, then invokes any supplied click handler ([source](../upstream/packages/banner/index.tsx#L112-L142)). Outside a Banner it receives the default no-op context setter ([source](../upstream/packages/banner/index.tsx#L15-L23)), so it does not itself establish a dismissal boundary.
- `BannerIcon` requires a `LucideIcon` and renders it at `16`; `BannerTitle` is a paragraph; `BannerAction` defaults to Button `outline`/`sm`; `BannerClose` defaults to Button `ghost`/`icon` and always renders the X icon ([source](../upstream/packages/banner/index.tsx#L67-L142)). Button variants, sizes, disabled behavior, and focus styles come from the local shadcn Button ([`button.tsx`](../upstream/packages/shadcn-ui/components/ui/button.tsx#L7-L60)).
- Demos use the full five-part compound layout ([`banner.tsx`](../upstream/apps/docs/examples/banner.tsx#L3-L19)), `inset` ([`banner-inset.tsx`](../upstream/apps/docs/examples/banner-inset.tsx#L3-L20)), and scoped `--primary`/`--primary-foreground` CSS variables for three colors ([`banner-themes.tsx`](../upstream/apps/docs/examples/banner-themes.tsx#L13-L68)). Those token overrides are demo styling; they do not add a Banner prop.

### Calendar

- This is a **feature-end-date grid**, not the shadcn date-picker component. `Feature` requires `id`, `name`, `startAt`, `endAt`, and `{id,name,color}` status ([source](../upstream/packages/calendar/index.tsx#L59-L71)); `CalendarBody` filters each current-month cell by `endAt` only ([source](../upstream/packages/calendar/index.tsx#L237-L246)). `startAt` is not read by this package implementation.
- `CalendarBody` provides a render prop `{ feature }`, displays at most three per day, and emits a “+N more” count ([source](../upstream/packages/calendar/index.tsx#L189-L192), [L261-L307](../upstream/packages/calendar/index.tsx#L261-L307)). `CalendarItem` renders the status-color dot and truncated name ([source](../upstream/packages/calendar/index.tsx#L459-L478)).
- Month/year are module-level Jotai atoms initialized from the current date, with exported read/write hooks ([source](../upstream/packages/calendar/index.tsx#L36-L47)). `CalendarProvider` only supplies `locale` (default `en-US`) and `startDay` (default `0`), plus layout/class props; it has no value/onChange props ([source](../upstream/packages/calendar/index.tsx#L480-L496)). Therefore the source evidences shared atom state rather than a conventional per-provider controlled API.
- Month/year pickers are internal popover/command comboboxes. They use locale formatting (`monthsForLocale`, `daysForLocale`) and `CalendarYearPicker` needs inclusive numeric `start` and `end` ([source](../upstream/packages/calendar/index.tsx#L88-L115), [L117-L177](../upstream/packages/calendar/index.tsx#L117-L177), [L322-L386](../upstream/packages/calendar/index.tsx#L322-L386)). The helper `Popover` portals content and the helper `Command` wraps cmdk ([`popover.tsx`](../upstream/packages/shadcn-ui/components/ui/popover.tsx#L8-L48), [`command.tsx`](../upstream/packages/shadcn-ui/components/ui/command.tsx#L16-L90)).
- **Source-visible edge case:** selecting the currently selected command item sends `""` ([source](../upstream/packages/calendar/index.tsx#L153-L160)); both picker setters call `Number.parseInt` without a guard ([month](../upstream/packages/calendar/index.tsx#L349-L352), [year](../upstream/packages/calendar/index.tsx#L377-L384)). This can write `NaN` into the corresponding atom.
- Pagination moves across December/January and the header honors `locale`/`startDay` ([source](../upstream/packages/calendar/index.tsx#L388-L426), [L436-L457](../upstream/packages/calendar/index.tsx#L436-L457)).
- **Documentation mismatch to keep in mind:** the component docs list `dndkit` and “Selectable date range” ([docs](../upstream/apps/docs/content/components/calendar.mdx#L5-L20)); this package's declared runtime dependencies do not include dndkit ([metadata](../upstream/packages/calendar/package.json#L6-L13)) and this implementation contains no range-selection API or selection state. Do not infer that feature from the docs or from the separate pattern catalog.
- Demos: the complete picker/pagination composition using Faker-generated data ([`calendar.tsx`](../upstream/apps/docs/examples/calendar.tsx#L3-L62)); the documented headless version omitting date controls ([`calendar-headless.tsx`](../upstream/apps/docs/examples/calendar-headless.tsx#L3-L38)); and the Roadmap block's identical calendar view ([`roadmap.tsx`](../upstream/apps/docs/examples/roadmap.tsx#L3-L14), [`roadmap.tsx`](../upstream/apps/docs/examples/roadmap.tsx#L287-L313)). Faker data and Roadmap's surrounding multi-view logic are demos, not calendar exports.
- The catalog separately lists 16 `packages/patterns/calendar` dialog/standard patterns ([`catalog/patterns/calendar.md`](../catalog/patterns/calendar.md)). They are patterns—not this `@repo/calendar` component API—and were not treated as usage examples or browser validation.

### Choicebox

- The root is a shadcn `RadioGroup` with `w-full`, so it exposes the underlying group props, including the demonstrated `value`/`onValueChange` controlled form and `defaultValue` demo form ([component](../upstream/packages/choicebox/index.tsx#L22-L26); [controlled demo](../upstream/apps/docs/examples/form.tsx#L171-L190); [uncontrolled demo](../upstream/apps/docs/examples/choicebox.tsx#L26-L43)).
- Composition is `ChoiceboxItem` → header/title/subtitle/description plus `ChoiceboxIndicator`. Item puts `value`/optional `id` in a private context; only Indicator turns that value into `RadioGroupItem` ([source](../upstream/packages/choicebox/index.tsx#L28-L64), [L66-L113](../upstream/packages/choicebox/index.tsx#L66-L113)). Calling Indicator outside Item throws ([source](../upstream/packages/choicebox/index.tsx#L37-L46)).
- The actual control is radio-only: `ChoiceboxIndicator` renders `RadioGroupItem`, whose local helper uses Radix RadioGroup and a radio indicator ([source](../upstream/packages/choicebox/index.tsx#L105-L113); [`radio-group.tsx`](../upstream/packages/shadcn-ui/components/ui/radio-group.tsx#L9-L45)). The docs' “radio or checkbox” wording ([docs](../upstream/apps/docs/content/components/choicebox.mdx#L10-L21)) is not evidenced by this implementation.
- `ChoiceboxItem`'s declared type includes RadioGroupItem props but it destructures only `className`, `children`, `value`, and `id`; it does not forward, for example, `disabled` to the control ([source](../upstream/packages/choicebox/index.tsx#L49-L64)). `ChoiceboxIndicator` does forward any props to `RadioGroupItem`, whose styling includes disabled styles ([indicator](../upstream/packages/choicebox/index.tsx#L105-L113); [helper](../upstream/packages/shadcn-ui/components/ui/radio-group.tsx#L22-L43)). Source therefore supports passing control-specific props to Indicator, but does not establish a complete disabled-card behavior.
- Selected-card styling comes from the local `FieldLabel` `has-data-[state=checked]` selectors, and the item uses a `FieldLabel` with `htmlFor={id}` ([choicebox](../upstream/packages/choicebox/index.tsx#L51-L63); [`field.tsx`](../upstream/packages/shadcn-ui/components/ui/field.tsx#L110-L125)). The implementation does **not** pass that item `id` into Indicator; if an explicit id-to-control association is required, source reading shows it must be considered at the Indicator layer. No keyboard/accessibility behavior was tested.
- Demos: default selection with subtitle ([`choicebox.tsx`](../upstream/apps/docs/examples/choicebox.tsx#L1-L45)); an inline visual layout supplied by caller `gridTemplateColumns` ([`choicebox-inline.tsx`](../upstream/apps/docs/examples/choicebox-inline.tsx#L1-L44)); and a controlled Event Type field in the Form block ([`form.tsx`](../upstream/apps/docs/examples/form.tsx#L1-L10), [`form.tsx`](../upstream/apps/docs/examples/form.tsx#L171-L190)). Inline is caller CSS, not an `inline` component prop.

## Architecture

All five are local, copyable package source in the upstream monorepo and depend on the local `@repo/shadcn-ui` aliases configured by their `tsconfig` files ([example alias configuration](../upstream/packages/announcement/tsconfig.json#L1-L13)). Announcement delegates its element/variants to Badge; Avatar Stack relies on the shadcn Avatar `data-slot`; Banner delegates buttons and a third-party controllable-state hook; Calendar combines Jotai/date-fns with local Button/Command/Popover; Choicebox combines local RadioGroup and Field primitives. The source is Tailwind-class based rather than package-CSS based.

## Start Here
