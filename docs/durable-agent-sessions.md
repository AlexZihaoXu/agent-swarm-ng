# Durable agent sessions — implementation contract

Status: implemented on `feat/durable-agent-sessions`; owner acceptance, merge and deployment pending. This is **private Pi working context**, not published chat or autonomous work recovery. The existing Prisma/SQLite platform database remains authoritative for accepted and published messages; do not add a second SQLite file for this milestone.

## Scope and trust boundary

- Keep one logical session per agent across private human chat, groups, and agent DMs. Each run still has one active execution slot and rebinds its current model, system prompt, explicitly granted tools, channel source, and publication permissions. Restored text is prior context, never a fresh instruction or a permission grant.
- Persist ordered Pi session entries (including completed user/assistant/tool exchanges and compaction entries) in private indexed records keyed by agent. Never expose them through channel history, browser events, activity APIs, or saved chat. Do not persist streaming deltas as valid completed messages.
- A completed session survives a normal turn boundary and backend restart. Existing agents without private session records begin from bounded saved-chat previews once; subsequent runs use the durable session rather than stacking the same previews again. Authorized history tools still read older/full chat from SQLite on demand.
- Current acceptance/publication transactions remain the source of truth for chat. An acknowledgment or other committed publication can precede its private Pi checkpoint; recovery includes bounded committed publication previews without duplicating chat records or replaying a side-effecting tool. Frozen turn checkpoints leave publication cursors conservative until inference is idle, so a delayed SQLite write cannot hide a later effect. A crash gap may repeat already-known text as a private recovery note, never republish it. Stop/crash leaves unfinished inference interrupted; **do not automatically requeue it** in this milestone.
- Preserve audience labels and execution-time channel grants. Removing a membership stops future group reads/publications; previously observed context is not retroactively unlearned. Likewise, deleting a group's canonical chat history does not reliably erase copies an agent already incorporated into its private working session or summary. A stronger erasure policy needs explicit scope (potentially dropping entire affected agent sessions), not a claim of selective text redaction. Internal session data and compaction summaries are sensitive private application data under `.local/` and must never be published as chat.

## Pi format and checkpoint boundaries

- The pinned Pi SDK (`0.85.1`) supports `SessionManager.inMemory(cwd, options, entries)` and returns an append-only header/entry tree. Rehydration reconstructs the active leaf and its compaction-aware model context. Keep the entry order and session ID; validate version, agent ownership, parent links, and sizes before loading untrusted/corrupt records.
- Pi appends completed `message_end` entries and compaction entries to its manager. Freeze a private snapshot at each complete turn/tool-result or completed compaction boundary **before** scheduling its SQLite write; a later model turn cannot contaminate that queued checkpoint. If interrupted mid-generation, load the last committed checkpoint and reconcile already published chat without treating partial text as an answer.
- The pinned SDK's compaction entry names `firstKeptEntryId` rather than embedding `retainedTail`. Keep the referenced entries so restore remains possible. The database records the active start position: on load it reads only the latest retained tail, its compaction entry and newer entries, re-rooting that in-memory tail while preserving original parent links and older private entries in indexed archive rows. The model receives the latest summary plus the kept tail, never the full archive. A failed compaction leaves the preceding checkpoint usable.
- Store checkpoints incrementally as ordered records, not by rewriting one unbounded JSONL or database field. Use short transactions and enforce per-entry/transaction bounds. Compaction, the active-start pointer and append update in one transaction. The archive remains available for future private retrieval/retention policies, not channel publication.

## Acceptance tests

1. Rehydrate an agent session after a completed human turn and a later backend restart: model-visible Pi context (including bounded tool results) is preserved, with no JSONL file and no raw assistant text in chat.
2. Alternate private, DM, and group inputs for one agent; context persists in one agent session, while a later tool call still obeys current audience/membership/DM grants.
3. Crash/Stop after a saved publication but before a private checkpoint: chat retains exactly one publication and the next run can see it; interrupted model work is not automatically restarted.
4. Restore before and after successful compaction, with summary and retained tail exactly once; failed/incomplete compaction falls back to the previous checkpoint. Older chat remains accessible only through authorized history tools.
5. Delete an agent: its private session records cascade without removing unrelated agents or provider connections. Startup/OpenAPI generation must not mutate session state.

## Verification and remaining limits

An isolated Prisma `migrate deploy` applied every migration including the session tables/index. Unit/integration tests exercise entry-tree round trips, incremental SQLite checkpoints and cascades, completed-context restoration after app rebuild, cross-channel continuity, publication-gap reconciliation, membership revocation, real Pi compaction with incomplete-summary fallback, multiple compacted active tails, and absence of internal output from public chat. A separate isolated Bun backend process was stopped and restarted with the same test database: the second request received the first request's private model output and tool result, while published chat and private entries remained distinct. No production database or credentials were used for that smoke test. The complete backend suite passed (160 tests in 39 files), along with backend/frontend typechecks, frontend production build, generated API drift check, whitespace checks, and six focused delete-dialog browser checks.

Provider-hidden state and an in-flight token stream cannot be restored exactly. Automatic replay of interrupted jobs, autonomous scheduling, cross-process coordination, selective erasure of previously observed content, and a user-facing private-session archive browser remain separate scope. Pi compaction summaries are lossy; archived rows remain private application data and are **not** channel history.
